### Drift, order effect, API join

- Drift: cowrie ρ = 0.256 (p = 0.41) — inconclusive. groundtruth_ssh
  ρ = 0.704 (p = 0.0012) is "significant" only because its per-run medians
  take two values, 15 ms and 16 ms (run 1 at 16 ms): a 1 ms rank artifact,
  not observable drift. Do not report it as drift.

### Clock resolution caveat (groundtruth_ssh, cowrie, llmhoneypot)

Every statistic whose value is below 0.05 s is **quantised, not measured**:
groundtruth_ssh median 0.015 / p95 0.031, cowrie 0.031 / 0.047, llmhoneypot
0.015 / 0.031. Over 720 completed commands the values pile up at ~15–16 ms and
~30–32 ms (groundtruth_ssh 15 ms ×403, 16 ms ×105, 31 ms ×77; llmhoneypot 15 ms
×408, 16 ms ×136, 31 ms ×87), i.e. scheduler-tick / RTT steps. groundtruth_ssh
run medians take only two values (15 ms and 16 ms), so its ρ = 0.70 "drift" is a
single tick flip; the cowrie and llmhoneypot correlations (run medians from
0.015 to 0.0315) are equally rank-limited. Differences of one tick (~1 ms) and
the `llmhoneypot` extra-vs-groundtruth value of 0.000 s are below the resolution
of these timings and should not be interpreted.
- Order effect: advshellm ρ = 0.144 (p = 0.0004), deceive ρ = −0.090
  (p = 0.049), beelzebub ρ = 0.049 (p = 0.34), vellmes ρ = 0.075 (p = 0.12) —
  small and inconsistent in sign; no usable position effect.
- API join (per command, 100% matched): median API duration 2.24–2.38 s for the
  SSH LLM targets (p95 5.5–9.1 s), galah 3.71 s (p95 18.2 s); non-API gap
  median 35–161 ms (SSH), 46 ms (galah).

## Anything surprising or inconsistent

1. `groundtruth_ssh` "drift" (ρ = 0.70, p = 0.001) is a 15/16 ms quantization
   artifact; do not cite it as a trend.
2. Beelzebub timeouts collapse from 16/180 (published, quiet) to 4/720 (prompt).
   Largest unexplained batch difference; leave as UNVERIFIED.
3. Beelzebub has 13/720 transcript-leakage rows and 2 oversized outputs; DECEIVE
   6 oversized and 2 leakage. Both are prompt-mode only in this batch.
4. Vellmes `ps_aux`/`env` time out in ~85–95% of runs. Vellmes has **45/720
timeouts, 675/720 completed** (6.25 % censored); any vellmes latency claim is
based on that subset, and its p95 (4.996 s) is conditional on completion.
5. Two upstream 502 read timeouts (advshellm run 6, deceive run 13) are the only
   non-200 proxy rows; no safety stop fired, and both are inside the slot call
   ranges.
6. The analyzer's `ci_determinism` resamples per-command values while the report
   header says "resample unit = run"; the latency and timeout CIs do resample
   runs. Left as is (documented here) rather than changing the metric mid-project.
7. galah run 14 made 17 upstream calls for 20 requests because 3 requests timed
   out before the proxy saw them (plus 1 that reached upstream). Not cache
   hits.

## Verdict

The Stage 4 data is clean and usable for the final report: every completeness,
field, proxy, timeout, masking, secret and container-lifecycle check passes, and
the corrected cost ($2.02) matches the bill. Nothing needs to be re-run. The only
item worth a second look before writing is the Beelzebub published-vs-Stage-4
timeout difference, which should be reported as a difference between batches
(quiet/5-run vs prompt/20-run) and not as a measured effect.
